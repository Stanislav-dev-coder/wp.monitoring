# Тестовое задание Intern/Junior DevOps-инженера от «RocketDev»

Благодарим за интерес, проявленный к нашей компании, мы это ценим!

Мы разработали тестовое задание, которое поможет вам взглянуть на возможные будущие задачи, а нам — оценить ваш текущий уровень знаний.

## Требования к ПО

- Docker, docker-compose
- Свежие Debian или Ubuntu
- Nginx - последняя стабильная версия
- WordPress + MySQL/MariaDB - последние стабильные версии (CMS открытая, чтобы не зависеть от лицензии)
- Prometheus, Grafana, node_exporter
- Ansible
- Certbot / самоподписанный сертификат

## Описание

1. В рамках ОС должны быть развёрнуты WordPress + MySQL, Nginx, Prometheus, Grafana с использованием Docker-контейнеров и docker-compose. Конфигурационные файлы должны находиться на хосте и монтироваться в контейнеры в режиме read-only.
2. Nginx должен выступать фронтендом и проксировать запросы:
   - полученные на имя site.local по HTTP/HTTPS - к WordPress
   - полученные на имя metrics.local по HTTP - к Grafana
3. Настроить SSL для site.local (самоподписанный сертификат допустим для тестового задания).
4. Организовать сбор общих метрик ОС в Prometheus через node_exporter.
5. В Grafana реализовать dashboard **OS General**: отправленный/полученный трафик, количество свободного места, количество файловых дескрипторов
6. Настроить базовую защиту сайта:
   - wp-admin и wp-login.php должны быть доступны только с ограниченного списка IP
   - Настроить fail2ban или iptables-правило для базовой защиты от брутфорса на уровне SSH

## Результат

Проект должен состоять из:

1. Набора конфигураций для каждого используемого ПО (nginx, prometheus, grafana, fail2ban);
2. docker-compose.yml, разворачивающего контейнеры с монтированием конфигов;
3. JSON-модели дашборда, готовой к импорту;
4. Краткого README: как запустить, какие решения принял и почему.

Проект должен быть загружен в публичный git-репозиторий.

## Бонус (не обязательно, плюс в карму)

- Описать весь процесс развёртывания Ansible-плейбуком вместо руками написанной инструкции в README;
- Простой CI-пайплайн (GitLab CI/GitHub Actions), проверяющий, что docker-compose config валиден и контейнеры стартуют перед мержем.
